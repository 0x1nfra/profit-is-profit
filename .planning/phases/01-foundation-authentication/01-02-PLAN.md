    1. Create or rewrite `src/middleware.ts` for Next.js route protection:
       - This middleware runs on every matched request and handles the routing logic for AUTH-03:
         - Landing page `/`: If user is authenticated AND setup complete → redirect to `/dashboard`
         - Setup page `/setup`: If user is NOT authenticated → redirect to `/`
         - Dashboard `/dashboard`: If user is NOT authenticated → redirect to `/`. If authenticated but NOT setup complete → redirect to `/setup`
         - API routes `/api/*`: Pass through (API routes handle their own auth)

    2. **Auth detection strategy** (must work in middleware context — no Zustand, no client state):
       - Option A (preferred): Check for a Supabase auth cookie. Use @supabase/ssr createServerClient to check session in middleware. If session exists, user is authenticated.
       - Option B (simpler): Check for a custom cookie set during the auth verify flow (e.g., 'pisp-auth' cookie set by /api/auth/verify response). Less secure but simpler for MVP.
       - Choose the approach that works reliably. If using Supabase SSR, install @supabase/ssr if needed.

    3. **Setup detection** in middleware:
       - For routes needing setup check (/dashboard), query Supabase to check if user has wallet records
       - Use supabase server client to query wallets table: `select('id').eq('user_id', userId).limit(1)`
       - If no wallets found → redirect to /setup
       - Cache this check via cookie if performance is a concern (set 'pisp-setup-complete' cookie after first successful check)

    4. **Matcher config**:
       ```typescript
       export const config = {
         matcher: ['/', '/setup/:path*', '/dashboard/:path*'],
       };
       ```

    5. **Important**: The /api/auth/verify route from Plan 01 should set appropriate cookies/headers so middleware can detect authenticated state. If Plan 01's implementation doesn't set cookies that middleware can read, update the verify route to also set a session cookie. Coordinate via the SUMMARY from Plan 01.

    6. Handle edge cases:
       - User with expired session (7-day TTL): middleware should redirect to landing
       - Static assets and _next paths: exclude from matcher
       - API routes: exclude from matcher (they self-auth)
  </action>
