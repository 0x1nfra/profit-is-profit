<task type="auto">
  <name>Task 2: Create Zustand wallet store with persistence and auth verify API route</name>
  <files>
    src/lib/stores/wallet-store.ts
    src/app/api/auth/verify/route.ts
  </files>
  <action>
    1. Create `src/lib/stores/wallet-store.ts` using Zustand with persist middleware:
       - State:
         - connectedAddress: string | null
         - isSetupComplete: boolean
         - lastAuthAt: number | null (timestamp of last message sign, for 7-day TTL)
         - sessionExpiry: number | null (lastAuthAt + 7 days in ms)
       - Actions:
         - setConnected(address: string): sets connectedAddress, lastAuthAt = Date.now(), sessionExpiry = Date.now() + 7*24*60*60*1000
         - setSetupComplete(complete: boolean)
         - isSessionValid(): boolean — returns true if sessionExpiry > Date.now()
         - reset(): clears all state to initial values (used on disconnect)
       - Persist config:
         - name: 'pisp-wallet-storage'
         - storage: createJSONStorage(() => localStorage)
       - Export as `useWalletStore`

    2. Create `src/app/api/auth/verify/route.ts` as POST endpoint:
       - Accept JSON body matching AuthVerifyRequest type (publicKey, message, signature)
       - Validate all fields are present, return 400 if missing
       - Verify the signature using tweetnacl or nacl.sign.detached.verify:
         - Decode publicKey from base58 using bs58
         - Decode signature from base58 using bs58
         - Verify message was signed by publicKey
       - If verification passes, use supabaseAdmin (from src/lib/supabase.ts) to:
         - Check if user exists in 'users' table by looking up wallets with this address
         - If no user exists, create one via supabaseAdmin.from('users').insert({}) then get the new user ID
         - Return { success: true, userId: user.id }
       - If verification fails, return 401 { success: false, error: 'Invalid signature' }
       - Import supabaseAdmin from @/lib/supabase (server-side admin client already exists)
       - Note: Do NOT use tweetnacl if bs58 + nacl creates issues. Instead use @noble/ed25519 or the built-in Web Crypto API with Ed25519. Prefer the simplest approach that works.
  </action>
  <verify>
    Run `pnpm typecheck` — should pass.
    Run `pnpm build` — should compile without errors.
    Verify wallet-store.ts exports useWalletStore hook.
    Verify API route exports POST function.
  </verify>
  <done>
    Zustand store persists wallet address and session TTL to localStorage. Auth verify API validates signatures and creates/finds user records in Supabase. 7-day session expiry tracked client-side.
  </done>
