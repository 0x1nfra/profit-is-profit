## Decisions Made
- Dual cookie approach: same JWT value in both pisp-auth (httpOnly, for middleware) and pisp-convex-token (non-httpOnly, for ConvexProviderWithAuth). httpOnly cookie can't be read by JavaScript, so a separate non-httpOnly cookie is necessary for the client-side Convex auth hook.
- Wallet public key as JWT sub: no DB user record needed — the Solana wallet address IS the user identity in Convex.
- 410 stubs remain on disk so any component still calling old routes gets an explicit error rather than silent failure.
- Setup detection moved fully client-side: middleware no longer tracks setup state; dashboard's useQuery(wallets) returns empty array for new users and redirects to /setup.
